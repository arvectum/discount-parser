# Discount Parser — требования к инфраструктуре

## Короткий ответ

Отдельный сервер для текущей версии не требуется.

Discount Parser может полностью работать на обычном ноутбуке заказчика под Windows 10/11 или macOS. Приложение, локальная SQLite-база, web-панель, scheduler и Telegram-бот запускаются на этом компьютере.

## Что необходимо

### Компьютер

Минимально:

- Windows 10/11 или актуальная macOS;
- 64-bit процессор;
- 2 CPU cores;
- 4 GB RAM;
- около 1 GB свободного места для приложения и начальной базы.

Рекомендуется для комфортной постоянной работы:

- 4 CPU cores или больше;
- 8 GB RAM или больше;
- 2–5 GB свободного места с запасом под историю базы, логи и XLSX-экспорты.

Парсер не использует GPU и не требует видеокарты, CUDA или локальной LLM.

### Интернет

Требуется обычный исходящий доступ в интернет по HTTPS.

Приложению нужен доступ:

- к сайтам-источникам скидок и промокодов;
- к Telegram Bot API;
- при обновлении приложения — к месту, откуда заказчик получает новую сборку.

Входящий доступ из интернета не нужен.

Web-панель по умолчанию слушает только:

```text
127.0.0.1:8765
```

Поэтому открывать порт на роутере, покупать домен, настраивать белый IP, HTTPS-сертификат или внешний firewall rule не требуется.

## База данных

Отдельный сервер базы данных не нужен.

Используется локальный SQLite-файл:

```text
discount_parser.db
```

В нём хранятся:

- предложения;
- история обнаружения;
- статусы;
- публикации;
- результаты запусков парсера;
- ручные исправления;
- сохранённые состояния источников;
- фильтры публикации.

Для текущего однопользовательского локального сценария этого достаточно.

## Что должно быть включено для автоматической работы

Если scheduler настроен, например, на сбор каждые 120 минут, компьютер должен в момент запуска быть:

1. включён;
2. не находиться в sleep/hibernation;
3. подключён к интернету;
4. с запущенным Discount Parser.

Если ноутбук выключен или спит, парсер, Telegram polling и scheduler в это время не выполняются.

После следующего запуска приложение продолжит работу с сохранённой SQLite-базой. Пропущенные во время выключения интервалы не означают потерю самой базы, но предложения, существовавшие на сайтах только во время простоя, могли не попасть в сбор.

## Практический режим для ноутбука

Если заказчику достаточно работы только в рабочее время, сервер не нужен.

Типичный сценарий:

```text
утром включили ноутбук
      ↓
запустили Discount Parser ярлыком
      ↓
bot + scheduler работают в течение рабочего дня
      ↓
вечером ноутбук выключили
```

Для такого режима достаточно обычного офисного ноутбука.

## Если требуется работа 24/7

Если заказчик хочет, чтобы:

- парсер собирал данные ночью;
- бот отвечал круглосуточно;
- автопубликация выполнялась независимо от рабочего ноутбука;
- работа не зависела от сна, перезагрузок и присутствия сотрудника,

тогда нужен постоянно включённый компьютер.

Это может быть:

- существующий офисный ПК, который не выключают;
- мини-ПК;
- Windows/Linux сервер;
- VPS.

Архитектура приложения не требует отдельного дорогого сервера. Для текущей нагрузки достаточно небольшой машины с 2 CPU cores, 2–4 GB RAM и несколькими GB диска, если она используется только под Discount Parser.

## Сон ноутбука

Для автоматической работы на ноутбуке рекомендуется запретить автоматический переход в сон на период, когда приложение должно собирать данные.

При этом экран можно выключать — это не мешает приложению. Важно именно не переводить сам компьютер в sleep/hibernation.

Если ноутбук закрывает крышку и после этого ОС переходит в сон, scheduler и Telegram-бот остановятся до пробуждения.

## Telegram

Нужны:

- Telegram-бот, созданный через BotFather;
- токен бота;
- Telegram-канал;
- бот должен быть администратором канала с правом публикации;
- Telegram user ID пользователя, которому разрешено управление ботом.

Отдельный Telegram-сервер или webhook не требуется. Текущая реализация использует polling, поэтому достаточно исходящего интернет-соединения с ноутбука.

## Корпоративная сеть и proxy

В обычной домашней/офисной сети дополнительная настройка не требуется.

Если в компании:

- весь интернет идёт только через корпоративный proxy;
- отдельные сайты заблокированы;
- Telegram API недоступен;
- HTTPS-трафик фильтруется,

может потребоваться настройка proxy/allowlist со стороны системного администратора компании.

## Резервное копирование

Для локальной установки главным пользовательским файлом является:

```text
discount_parser.db
```

Также следует сохранять:

```text
.env
```

Для простого резервного копирования достаточно периодически копировать эти файлы, когда приложение остановлено.

Перед автоматизацией backup отдельным механизмом рекомендуется определить требуемый заказчиком срок хранения истории.

## Что НЕ требуется

Для текущего локального варианта не нужны:

- отдельный сервер;
- Docker;
- PostgreSQL;
- Redis;
- nginx;
- домен;
- публичный IP;
- SSL-сертификат;
- GPU;
- отдельная база данных;
- установленный Python у конечного пользователя (в delivery-сборке runtime встроен);
- Git;
- IDE.

## Рекомендуемая формулировка для заказчика

> Для работы парсера достаточно обычного ноутбука Windows или macOS с доступом в интернет. Отдельный сервер не требуется. Все данные хранятся локально на ноутбуке, а управление выполняется через локальную web-панель. Важно учитывать, что автоматический сбор и Telegram-бот работают только пока ноутбук включён, не находится в спящем режиме и запущено приложение. Если потребуется круглосуточная работа 24/7 независимо от ноутбука сотрудника, приложение можно перенести на небольшой постоянно включённый ПК или сервер без изменения основной логики.
