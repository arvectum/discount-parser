# Discount Parser — доставка заказчику и веб-интерфейс

## Что получает заказчик

Заказчику не нужно передавать исходный репозиторий, Git, Python или инструкции по созданию `.venv`.

Для доставки собираются два отдельных пакета:

- `discount-parser-windows` — для Windows 10/11;
- `discount-parser-macos` — для macOS.

Пакеты формируются GitHub Actions workflow `.github/workflows/build-delivery.yml` и содержат встроенный Python runtime через PyInstaller.

## Windows

Заказчик распаковывает архив и запускает:

```text
install.bat
```

Установщик:

1. копирует программу в `%LOCALAPPDATA%\DiscountParser`;
2. подготавливает SQLite-базу и выполняет миграции;
3. создаёт ярлык `Discount Parser` на рабочем столе.

После этого папка с исходным архивом для работы программы не нужна.

## macOS

Заказчик распаковывает архив и запускает:

```text
install.command
```

Установщик:

1. копирует программу в `~/Applications/DiscountParser`;
2. подготавливает SQLite-базу и выполняет миграции;
3. создаёт `Discount Parser.command` на рабочем столе.

На macOS неподписанное приложение или скрипт может потребовать стандартное подтверждение Gatekeeper через `Открыть` / `Open Anyway`. Для полностью бесшовной коммерческой доставки следующим уровнем упаковки будет signed/notarized `.app`/`.pkg`.

## Первый запуск

Пользователь дважды нажимает ярлык `Discount Parser`.

Программа:

1. запускает локальный веб-сервер только на `127.0.0.1`;
2. автоматически открывает браузер;
3. проверяет, завершена ли первичная настройка Telegram;
4. если настройки отсутствуют — открывает мастер настройки;
5. после сохранения — открывает панель управления.

По умолчанию веб-интерфейс доступен по адресу:

```text
http://127.0.0.1:8765
```

Он не публикуется в интернет.

## Какие Telegram-данные нужны

Для работы не требуется вручную заполнять `.env`.

Мастер запрашивает:

### 1. Bot Token — обязательно

Токен, выданный `@BotFather`.

Пример формата:

```text
123456789:AA...
```

### 2. Имя бота — необязательно

Используется только как удобная подпись в интерфейсе. Telegram API не требует его для авторизации.

### 3. Telegram-канал — обязательно

Можно указать:

```text
@channel_username
```

или числовой chat ID формата `-100...`.

Бот должен быть добавлен администратором канала с правом публикации сообщений.

### 4. Telegram user ID администратора — обязательно

Это числовой ID пользователя, которому разрешено управлять ботом.

Можно задать несколько ID через запятую.

## Что происходит с `.env`

`.env` является внутренним техническим файлом. Пользователь не обязан его открывать или редактировать.

Мастер настройки сам создаёт/обновляет:

```dotenv
DP_TELEGRAM_BOT_TOKEN=...
DP_TELEGRAM_BOT_NAME=...
DP_TELEGRAM_CHANNEL_ID=...
DP_TELEGRAM_ADMIN_IDS=...
```

Токен никогда не выводится обратно на dashboard.

## Панель управления

После первичной настройки открывается dashboard.

На нём сейчас доступны:

- количество всех предложений;
- `ready`;
- `needs_review`;
- `published`;
- `expired`;
- статус Telegram-бота;
- кнопка запуска/остановки Telegram-бота;
- статус scheduler;
- кнопка запуска/остановки scheduler;
- кнопка `Запустить сбор сейчас`;
- последняя ошибка ручного запуска парсинга;
- список источников, их последний статус и количество полученных записей;
- переход к настройкам Telegram.

## Логика работы

```text
Ярлык на рабочем столе
        ↓
Discount Parser executable
        ↓
локальный web server 127.0.0.1:8765
        ↓
проверка Telegram settings
        ├─ нет → мастер настройки → сохранить
        └─ есть
        ↓
Dashboard
        ├─ Парсер: запустить сейчас
        ├─ Telegram Bot: start / stop
        ├─ Scheduler: start / stop
        └─ Sources / status / counters
```

## Сборка пакетов для передачи заказчику

Workflow:

```text
.github/workflows/build-delivery.yml
```

Запускается:

- вручную через `workflow_dispatch`;
- автоматически при push тега `v*`.

Сборка выполняется отдельно на `windows-latest` и `macos-latest`, потому что PyInstaller binary нельзя собрать один раз для разных ОС.

Перед публикацией workflow выполняет frozen migration smoke непосредственно собранным executable.

## Что передавать заказчику

Не нужно передавать весь GitHub-проект.

Передаётся только соответствующий его ОС artifact:

```text
discount-parser-windows
```

или

```text
discount-parser-macos
```

Внутри пользователь видит установочный файл и папку `app`. После установки он работает только через ярлык и веб-интерфейс.
