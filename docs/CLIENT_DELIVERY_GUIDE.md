# Discount Parser — поставка заказчику

Этот документ описывает пользовательскую поставку. Заказчику не требуется Python, Git, pip, виртуальное окружение или ручное редактирование `.env`.

## Что передаётся заказчику

Сборки создаются отдельно под платформу и архитектуру.

### Windows

Предпочтительный файл поставки:

```text
DiscountParser-Setup.exe
```

Текущая Windows-сборка — x64. Установщик содержит приложение со встроенным Python runtime.

### macOS

Готовятся отдельные frozen packages:

```text
discount-parser-macos-arm64
discount-parser-macos-intel
```

Внутри пакета есть `install.command`. Он устанавливает runtime и создаёт обычный `Discount Parser.app` в `~/Applications` и ярлык-приложение на рабочем столе. Обычный запуск приложения не открывает Terminal.

Для внешней коммерческой поставки без предупреждений Gatekeeper нужен Apple signing/notarization.

## Windows: установка

1. Запустить `DiscountParser-Setup.exe`.
2. Пройти стандартный мастер установки.
3. Программа устанавливается в профиль текущего пользователя.
4. Автоматически выполняется миграция локальной SQLite-базы.
5. На рабочем столе и в меню Пуск создаётся ярлык `Discount Parser`.
6. На последнем шаге можно сразу открыть приложение.

Отдельно устанавливать Python или Git не нужно.

## macOS: установка

1. Выбрать пакет под архитектуру Mac: Apple Silicon (ARM64) или Intel.
2. Запустить `install.command` один раз.
3. Runtime устанавливается в `~/Applications/DiscountParser`.
4. Автоматически выполняется миграция SQLite.
5. Создаётся `~/Applications/Discount Parser.app` и desktop launcher `Discount Parser.app`.
6. Дальнейшая работа идёт обычным двойным кликом по приложению, без Terminal.

Повторная установка обновляет runtime **без удаления** пользовательских `.env` и `discount_parser.db`.

## Первый запуск

После запуска ярлыка приложение:

1. проверяет, не запущена ли уже локальная панель;
2. если панель уже работает, просто открывает её в браузере, не создавая второй экземпляр;
3. иначе запускает локальный web server только на `127.0.0.1`;
4. автоматически открывает браузер;
5. проверяет, завершена ли первичная настройка;
6. если Telegram-настройки отсутствуют, показывает мастер настройки;
7. после успешного сохранения packaged-версия запускает Telegram-бота и scheduler;
8. открывает dashboard.

Адрес панели по умолчанию:

```text
http://127.0.0.1:8765
```

Она доступна только на текущем компьютере.

## Какие данные вводятся при первом запуске

Обязательные поля:

- Bot Token — токен, полученный у BotFather;
- Telegram-канал — `@username` канала или числовой chat ID;
- Telegram user ID администратора — пользователь, которому разрешено управлять ботом.

Необязательное поле:

- имя бота — подпись для интерфейса.

Отдельный Telegram bot ID вводить не требуется: Telegram определяет бота по токену.

После сохранения приложение самостоятельно создаёт локальный `.env`. Пользователь не должен открывать или редактировать его вручную.

## Что доступно в web-панели

### Главная

Отображаются:

- общее количество предложений;
- готовые к публикации;
- требующие проверки;
- опубликованные;
- истёкшие;
- состояние parser / bot / scheduler;
- расписание;
- источники;
- фильтр публикации;
- очередь;
- XLSX export/import.

### Предложения

Отдельная страница позволяет:

- искать по названию, магазину и промокоду;
- фильтровать по статусу, категории и типу;
- открывать карточку Offer;
- видеть provenance — из каких источников и когда пришло предложение.

### Журнал

Показываются последние ParseRun:

- источник;
- статус;
- время начала/окончания;
- fetched/new/updated/review counters;
- число ошибок;
- текст последней ошибки.

### Система

Показываются:

- состояние Telegram-бота и scheduler;
- PID процессов;
- последние строки `logs/bot.log` и `logs/scheduler.log`;
- кнопки очистки логов;
- кнопка `Завершить Discount Parser`.

Кнопка завершения останавливает bot, scheduler и локальную web-панель. После этого приложение запускается снова обычным ярлыком.

### Парсер

Можно вручную запустить сбор со всех включённых источников и увидеть состояние последнего запуска.

### Telegram-бот

Можно запускать и останавливать управляющего Telegram-бота.

### Scheduler

Можно запускать и останавливать автоматическое расписание парсинга, maintenance и autopost.

В packaged-режиме bot и scheduler запускаются автоматически после завершённой настройки.

### Расписание

Расписание настраивается прямо в браузере. Пользователь может менять:

- интервал автоматического сбора в минутах;
- интервал автопостинга в минутах;
- час и минуту ежедневного maintenance;
- количество дней без обновления, после которого undated offer переводится на review.

Если scheduler уже запущен, после сохранения новых значений web-панель автоматически перезапускает его, чтобы новые интервалы применились сразу.

### Источники

В web-панели показываются все доступные источники, их состояние, результат последнего запуска и количество полученных записей.

Для каждого источника доступны кнопки:

```text
Включить
Выключить
```

Состояние `enabled/disabled` хранится в SQLite и имеет приоритет над исходным `config/sources.yaml`. Поэтому пользовательский выбор сохраняется при обновлении приложения.

Отключённый источник действительно пропускается и при ручном сборе, и при scheduler-run.

### Очередь публикации

Web UI использует тот же publication ledger и тот же фильтр, что Telegram `/queue` и autopost.

Из панели можно:

- увидеть следующие предложения;
- открыть исходную страницу;
- опубликовать предложение в Telegram-канал;
- отклонить предложение.

Повторная публикация одного Offer в тот же канал блокируется publication ledger.

### Фильтр публикации

Из браузера настраиваются:

- минимальный процент скидки;
- категория;
- подкатегория;
- тип предложения;
- магазин;
- максимальное количество публикаций за цикл;
- включение/выключение autopost.

### XLSX

Из панели можно:

1. скачать `offers.xlsx`;
2. исправить `category` и `subcategory`;
3. загрузить файл обратно.

Ручные исправления сохраняются как manual override и имеют приоритет над автоматической классификацией.

## Где хранятся данные

Локально на компьютере заказчика хранятся:

```text
.env
  Telegram-настройки и параметры расписания

discount_parser.db
  SQLite-база, история Offer, ParseRun, Publication,
  manual overrides и пользовательское состояние источников

logs/
  bot.log и scheduler.log

config/
  исходные определения источников и taxonomy
```

Данные не требуют отдельного сервера базы данных.

## Обновление

Обновление поставляется новой версией installer/package. Пользователь не выполняет `git pull` или `pip install`.

При обновлении сохраняются пользовательские:

- `.env`;
- `discount_parser.db`;
- состояние источников в SQLite;
- runtime logs.

Миграции БД выполняются новым установщиком автоматически.

## Удаление

Windows `Setup.exe` создаёт стандартную запись приложения для удаления. Удаление программы и удаление пользовательской базы рассматриваются отдельно, чтобы случайно не удалить историю без явного выбора пользователя.

```text
       ↓

       │                         ↓
       нет                  сохранить настройки
       │                         ↓
       │                 bot + scheduler start
       │                         ↓
       └────────────────→ Dashboard
                              ↓
         Главная / Предложения / Журнал / Система
```
